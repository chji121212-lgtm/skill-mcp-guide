## 1. Skill이란?

Skill(스킬)은 AI가 특정 작업을 반복해서 잘 수행하도록 **절차·규칙·참고 자료를 묶어 놓은 것**입니다. 여기서 다루는 것은 `SKILL.md`를 사용하는 Agent Skills 방식입니다.

예를 들어 AI에게 매번 다음과 같이 말한다고 생각해 봅시다.

> 리눅스 명령어를 설명할 때 뜻, 기본 문법, 사용 예시, 주의사항 순서로 알려줘. 초보자도 이해할 수 있게 설명해줘.

이 지침을 스킬로 저장하면, 지원하는 AI 프로그램이 필요할 때 읽어 활용할 수 있습니다. 일회성 요청을 재사용 가능한 작업 지침으로 만드는 셈입니다.

핵심 파일은 `SKILL.md`입니다. 이름과 사용 조건을 적는 부분, 실제 지침을 적는 부분으로 구성합니다. 필요하면 Python 코드나 참고 문서도 함께 넣습니다. 간단한 설명용 스킬은 코드 없이 만들 수 있습니다. [1]

**스킬을 만든다고 AI 모델 자체를 재학습시키는 것은 아닙니다.** 또한 지침만 적는다고 새로운 시스템 접근 권한이 생기지는 않습니다.

## 2. MCP란?

MCP는 **Model Context Protocol**의 약자입니다. AI 프로그램과 외부 도구·데이터가 정해진 방식으로 통신하도록 하는 표준입니다. ‘프로토콜’은 서로 정보를 주고받는 규칙이라는 뜻입니다. [2]

도서관에 비유하면, Skill은 ‘자료를 찾아 정리하는 업무 지침’, MCP는 ‘자료 검색 시스템에 요청하고 답을 받는 공통 규칙’에 가깝습니다.

| 용어 | 쉬운 설명 |
| --- | --- |
| MCP 호스트 | 사용자가 사용하는 AI 프로그램 |
| MCP 클라이언트 | 그 프로그램 안에서 MCP 서버와 통신하는 부분 |
| MCP 서버 | 도구나 데이터를 MCP 방식으로 제공하는 프로그램 |
| Tool | 덧셈, 문서 검색 등 호출할 수 있는 기능 |
| Resource | 프로그램이 읽을 수 있도록 제공하는 자료 |
| Prompt | 서버가 제공하는 재사용 가능한 프롬프트 틀 |

‘MCP를 만든다’는 말은 보통 **MCP 표준을 따르는 서버와 도구를 구현한다**는 뜻입니다. 표준 자체를 새로 만드는 것은 아닙니다.

서버라고 해서 별도 컴퓨터가 반드시 필요한 것은 아닙니다. 내 PC에서 실행되는 프로그램도 MCP 서버가 될 수 있습니다. 외부 웹서비스 없이 계산 기능만 제공할 수도 있습니다. [2][3]

## 3. 두 가지의 차이

| 구분 | Skill | MCP |
| --- | --- | --- |
| 핵심 질문 | 어떤 절차와 기준으로 일할까? | 어떤 방식으로 도구·데이터를 연결할까? |
| 성격 | 재사용 가능한 지침과 자료 묶음 | 통신 표준 |
| 우리가 만드는 것 | 스킬 폴더와 `SKILL.md` | MCP 서버 프로그램과 도구 |
| 간단한 예 | 명령어 설명을 일정한 순서로 작성 | 덧셈 도구를 호출해 계산값 반환 |
| 코드 필요 여부 | 지침만으로도 가능 | 직접 서버를 만들 때 일반적으로 필요 |
| 별도 실행 프로그램 | 설명만 하는 스킬은 불필요 | 도구를 제공하는 서버가 실행되어야 함 |
| 단독 사용 | MCP 없이 사용 가능 | 별도 Skill 없이 사용 가능 |
| 함께 사용 | MCP 도구의 사용 절차를 안내 | Skill이 활용할 기능을 제공 |

이 표는 역할을 이해하기 위한 구분입니다. Skill에도 실행 코드가 포함될 수 있고, MCP 서버에도 사용 지침이나 프롬프트가 포함될 수 있습니다. 둘은 서로를 대체하는 관계가 아닙니다.

## 4. 어떤 순서로 만들까?

**처음 배우는 순서:** 간단한 Skill → 간단한 MCP 서버 → 두 가지 연결.

1. 하고 싶은 작업을 한 문장으로 정합니다.
2. 설명 방식만 정하면 되는지, 실제 도구 호출이 필요한지 구분합니다.
3. 설명 방식이면 먼저 Skill을 작성합니다.
4. 도구가 필요하면 이미 사용 가능한 도구가 있는지 확인합니다.
5. 직접 구현해야 한다면 핵심 기능을 먼저 만들고 MCP 도구로 노출합니다.
6. 실제 입력을 넣어 결과를 확인합니다.
7. 반복 작업의 순서와 오류 처리 방법을 Skill에 정리합니다.

개발 순서는 항상 고정되어 있지는 않습니다. 예를 들어 계산 프로그램이 이미 있다면 MCP로 연결한 다음 Skill을 작성해도 됩니다. Python이나 EXE를 먼저 만들어야만 스킬을 만들 수 있는 것도 아닙니다.

## 5. 실습 A: 리눅스 설명 Skill

**목표:** `pwd` 같은 명령어를 요청하면 정해진 형식으로 설명하는 스킬 만들기.

### ① 폴더와 파일 만들기

`linux-command-guide`라는 폴더를 만들고 그 안에 `SKILL.md`를 만듭니다.

Windows 메모장을 사용한다면 ‘다른 이름으로 저장’에서 파일 형식을 ‘모든 파일’로 선택하고 UTF-8로 저장합니다. 실제 파일명이 `SKILL.md.txt`가 되지 않도록 확장자를 확인합니다.

### ② 다음 내용 넣기

```markdown
---
name: linux-command-guide
description: 리눅스 초보자가 명령어의 뜻, 문법, 사용 예시를 요청할 때 사용한다. 실제 명령 실행이나 서버 설정 변경은 수행하지 않는다.
---

# 리눅스 명령어 설명

1. 요청한 명령어를 한 문장으로 설명한다.
2. 기본 문법을 코드 블록으로 보여준다.
3. 안전한 사용 예시 한 개와 예상 결과를 설명한다.
4. 주의할 점을 짧게 덧붙인다.
5. 한국어와 쉬운 용어를 사용한다.
6. 실제 실행하지 않은 결과는 반드시 예시라고 표시한다.
7. 명령어 이름이 불명확하면 먼저 확인한다.
```

### ③ 지원하는 AI 프로그램에 등록하기

GitHub에 파일을 올리는 것만으로 AI에 자동 등록되지는 않습니다. 사용하는 AI 프로그램의 스킬 등록 기능이나 지정된 폴더에 배치해야 합니다.

**로컬 Codex CLI 예:** 작업 프로젝트의 `.agents/skills/linux-command-guide/SKILL.md`에 배치합니다. 해당 프로젝트에서 Codex를 열고 `/skills` 목록에 나타나는지 확인합니다. 이것은 로컬 Codex 기준이며, 웹 AI 서비스에 그대로 적용되는 설치 방법은 아닙니다. [1]

### ④ 요청하고 확인하기

Codex CLI에서 다음과 같이 요청합니다.

```text
$linux-command-guide를 사용해서 pwd를 설명해줘.
```

원하는 답변 예시:

> **뜻:** 현재 작업 중인 디렉터리의 경로를 보여줍니다.  
> **문법:** `pwd`  
> **예시:** 실행 결과로 `/home/student` 같은 경로가 나옵니다. 실제 경로는 환경에 따라 다릅니다.  
> **주의:** 파일 목록을 보여주는 명령어는 아닙니다.

**확인 기준:** 뜻·문법·예시·주의사항이 나오는지, 실행한 적 없는 결과를 실제 결과처럼 말하지 않는지 봅니다.

## 6. 실습 B: 덧셈 MCP 서버

**목표:** AI가 `sum_values` 도구를 호출하면 두 정수의 합을 반환하기.

이 실습은 **Windows PowerShell + Python 3.10 이상 + 로컬 Codex CLI가 설치된 환경**을 가정합니다. 웹 ChatGPT 입력창에 명령어를 붙여 넣는 방식이 아닙니다.

예제는 공식 Python SDK의 **v1 계열 API**를 사용합니다. 아래 설치 명령에서 `<2`를 지정해 v2 API와 섞이지 않게 합니다. 최신 계열의 제작 방법은 공식 문서를 확인해야 합니다. [4]

### ① 폴더와 Python 가상환경 만들기

PowerShell을 열고 한 줄씩 실행합니다.

```powershell
mkdir mcp-sum-demo
cd mcp-sum-demo
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install "mcp>=1.12,<2"
```

가상환경은 이 예제에 필요한 패키지를 따로 설치하는 공간입니다. 별도의 활성화 명령 없이 그 안의 Python을 직접 실행합니다.

### ② `server.py` 만들기

`mcp-sum-demo` 폴더에 아래 내용을 `server.py`로 저장합니다.

```python
from mcp.server.fastmcp import FastMCP

app = FastMCP("sum-demo")


@app.tool()
def sum_values(left: int, right: int) -> int:
    """Return the sum of two integers supplied by the caller."""
    return left + right


if __name__ == "__main__":
    app.run(transport="stdio")
```

`@app.tool()`은 함수를 MCP 도구로 등록합니다. `stdio`는 같은 컴퓨터에서 표준 입력·출력으로 통신하는 방식입니다. 이 방식에서는 일반 안내 문구를 `print()`로 표준 출력에 섞지 않습니다.

### ③ 계산 기능 먼저 확인하기

같은 폴더의 PowerShell에서 실행합니다.

```powershell
.\.venv\Scripts\python.exe -c "from server import sum_values; print(sum_values(7, 5))"
```

예상 결과는 `12`입니다. 이 단계는 Python 계산 함수만 확인하며, MCP 연결 성공을 뜻하지는 않습니다.

### ④ Codex CLI에 MCP 서버 등록하기

아래는 **Codex CLI가 설치되고 로그인된 경우**의 명령입니다. 파일 위치를 현재 폴더에서 절대 경로로 구해 등록합니다.

```powershell
$demoPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
$demoServer = (Resolve-Path .\server.py).Path
codex mcp add sum-demo -- "$demoPython" "$demoServer"
codex mcp list
```

Codex가 등록된 명령으로 서버를 실행하므로, 다른 터미널에서 `server.py`를 미리 켜 둘 필요는 없습니다. [3]

### ⑤ AI를 통해 실제 도구 호출 확인하기

Codex를 열고 `/mcp`에서 연결 상태를 확인한 뒤 요청합니다.

```text
sum-demo의 sum_values 도구를 실제로 호출해서 7과 5를 더해줘.
```

**확인 기준:** 도구 호출 기록에 `sum_values`와 입력값이 나타나고, 반환값이 `12`인지 확인합니다. AI가 말로만 ‘12’라고 답했다면 MCP 동작을 검증한 것이 아닙니다.

### 실행이 안 될 때

| 증상 | 확인할 사항 |
| --- | --- |
| `py` 명령을 찾을 수 없음 | Python 설치와 Windows 실행 경로 확인 |
| `No module named mcp` | 위 가상환경의 Python으로 설치·실행했는지 확인 |
| `mcp.server.fastmcp`를 찾을 수 없음 | SDK가 예제의 v1 계열인지 확인 |
| `codex` 명령을 찾을 수 없음 | Codex CLI 설치 여부 확인 |
| 도구가 보이지 않음 | 등록 경로, `/mcp` 연결 상태, 서버 오류 확인 |
| `server.py`를 실행해도 화면이 조용함 | stdio 서버는 요청을 기다릴 수 있음. 종료는 Ctrl+C |

이 문서의 명령은 독자가 자기 환경에서 따라 하기 위한 예시입니다. Python 설치, Codex 로그인, 실제 MCP 연결은 독자의 PC에서 확인해야 합니다.

## 7. 둘을 함께 사용하기

덧셈 결과를 ‘입력값 → 계산값 → 설명’ 순서로 보여주는 Skill을 만든다고 가정합니다.

1. 사용자가 “7과 5를 더해줘”라고 요청합니다.
2. AI가 Skill의 설명 절차를 읽습니다.
3. 사용 가능한 `sum_values` MCP 도구를 호출합니다.
4. 서버가 `12`를 반환합니다.
5. AI가 Skill의 출력 형식에 맞춰 결과를 설명합니다.

Skill에는 다음과 같은 지침을 추가할 수 있습니다.

> 덧셈 요청이면 연결된 `sum_values` 도구를 호출한다. 도구가 없거나 실패하면 그 사실을 설명한다. 성공하면 입력값과 반환값을 보여준다. 직접 계산한 값을 도구의 반환값이라고 표현하지 않는다.

도구 이름을 지침에 적는 것만으로 연결되지는 않습니다. MCP 서버 등록과 실행이 별도로 되어 있어야 합니다.

## 8. 자주 헷갈리는 내용

**Q. 스킬을 만들려면 Python을 알아야 하나요?**  
설명 절차를 정하는 스킬은 글만으로 만들 수 있습니다. 계산·파일 변환 같은 실행 기능이 필요할 때 코드를 추가합니다.

**Q. `.py` 파일을 만들면 바로 MCP인가요?**  
아닙니다. MCP 방식으로 기능을 제공하고, 이를 지원하는 클라이언트와 연결되어야 합니다.

**Q. MCP는 API와 같은 뜻인가요?**  
API는 프로그램 간 기능 사용 방법이라는 넓은 개념입니다. MCP는 AI 앱과 도구·데이터를 연결하기 위한 특정 표준입니다. MCP 서버 내부에서 다른 서비스의 API를 호출할 수도 있습니다.

**Q. GitHub에 올리면 다른 사람의 AI에도 자동 등록되나요?**  
아닙니다. 다른 사람이 파일을 내려받고 해당 AI 프로그램에 맞게 스킬을 등록하거나 MCP 서버를 연결해야 합니다.

**Q. 서버를 만들면 반드시 인터넷에 공개해야 하나요?**  
아닙니다. 이 예제처럼 내 PC에서만 실행하고 연결할 수 있습니다.
